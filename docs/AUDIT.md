## 1. Executive Summary

FinTrack-AI (Personal OS 3.0.0) представляет собой зрелую, функционально богатую персональную экосистему управления финансами, автомобилем, задачами, целями и расчётом заработной платы. Архитектура построена на базе SPA (React 18 + TypeScript + Vite + Tailwind CSS) с бэкендом на Supabase (PostgreSQL, Row Level Security, Auth, Edge Functions) и развёртыванием на GitHub Pages.

В системе реализовано бесшовное сосуществование классического финансового леджера и нового модуля зарплатного учёта:
1. **Профиль «Моя работа» (5/2):** почасовая ставка (442 ₽/ч на испытательном сроке 1 месяц, далее 497 ₽/ч чистыми, без вычета НДФЛ), гибкий учёт фактически отработанных часов против плановых 8 ч/день с учётом реального производственного календаря.
2. **Профиль «Смены девушки» (2/2):** сменный и сдельный учёт (базовая ставка 2 415 ₽, праздничная 4 600 ₽, сдельная ставка 1.75 ₽ за дело, расчёт чередования смен `Math.round((d - start)/86400000) % 4 < 2`).
3. **Безопасная интеграция выплат:** начисленная зарплата не попадает в фактический денежный баланс автоматически, исключая задвоения; запись в леджер формируется только по явному подтверждению выплаты.

**Текущее техническое состояние:**
- Сборка (`npm run build`): **PASS** (чистая компиляция Vite + tsc, Service Worker precache).

## 2. Architecture

- **Клиентская часть:**
  - `React 18`, `TypeScript` в строгом режиме, `Vite`, `Tailwind CSS`.
  - Маршрутизация через `HashRouter` (необходимо для надежной работы на GitHub Pages без серверных rewrite-правил).
  - Управление состоянием сервера и кэширование: `@tanstack/react-query` v5. Запросы нормализованы по ключам таблиц и диапазонам дат.
  - Дизайн-система «FinanceDesign»: унифицированные токены (`ink`, `panel`, `rail`, `line`, `amber`, `cyan`, `warn`, `red`), отсутствие дублирующих UI-примитивов.
- **Бэкенд и данные:**
  - Supabase PostgreSQL: централизованный источник правды.
  - Строгая изоляция пользователей на уровне БД через Row Level Security (RLS) с предикатом `auth.uid() = user_id`.
  - Двунаправленная синхронизация авто-расходов с леджером через триггеры PostgreSQL.
- **Интеграция Telegram:**
  - Supabase Edge Functions (`supabase/functions/telegram-webhook`) на Deno с проверкой секретного токена `x-telegram-bot-api-secret-token`.
  - Сервисный доступ `SUPABASE_SERVICE_ROLE_KEY` изолирован исключительно внутри Edge Functions. Клиент браузера использует только публичный анонимный ключ.

## 3. Implemented

1. **Единый финансовый леджер (`finance_operations`):**
   - Учёт доходов и расходов с поддержкой категорий, тегов, заметок и умного парсинга текста (`+1200 бензин`, `зарплата 150к`).
   - Фильтрация по типам, категориям, диапазонам дат, поиск и экспорт (CSV / JSON).
2. **Модуль зарплаты (`salary_profiles`, `salary_rates`, `salary_work_days`, `salary_payments`, `salary_goals`):**
   - Профили с графиками 5/2 (почасовая ставка с учётом испытательного срока) и 2/2 (сдельная/сменная оплата, праздничные смены, учёт кейсов).
   - Интерактивный календарь смен с возможностью ручного ввода и редактирования фактических часов/дел.
   - Месячный план/факт, расчёт аванса (25 число) и зарплаты (10 число).
   - Прогнозирование заработка до конца месяца с учётом динамики и оставшихся смен.
   - Безопасное подтверждение получения выплаты с атомарным созданием операции дохода в леджере.
   - Интеграция с Telegram-ботом (`/salary`, `/shift`, `/hours`, inline-кнопки фиксации часов).
3. **Регулярные платежи и Cash Flow:**
   - Подписки и периодические платежи (`recurring_payments`).
   - Детерминированный движок прогнозирования денежного потока (`buildCashFlowForecast`) на горизонт до 730 дней.
   - Учёт ручного стартового баланса и безопасного минимума (safe floor).
4. **Учёт долгов и кредитов:**
   - Управление кредитами, кредитными картами и долгами с процентными ставками и минимальными платежами.
   - Атомарный RPC-платеж с одновременным списанием в расход леджера.
   - Калькулятор досрочного погашения методом лавины (Avalanche).
5. **Автомобильный блок:**
   - Мульти-автомобильный учёт: заправки, сервис/ремонты, прочие расходы, напоминания по пробегу и дате.
   - Калькулятор TCO (совокупная стоимость владения) и сравнение сценариев владения.
   - Автоматическая синхронизация связанных записей авто с финансовыми операциями через триггер БД.
6. **Задачи, цели, заметки, обучение и IT-команды:**
   - Задачи с дедлайнами и рекуррентностью.
   - Финансовые цели с отслеживанием накоплений.
   - База знаний IT-команд с быстрым копированием в буфер.
   - Заметки с закреплением и поиском по тегам.
7. **PWA & Offline:**
   - Манифест PWA, service worker с прекэшированием ассетов и поддержкой оффлайн-оболочки.

   - *Проблема:* Хук `useEffect` в `src/data/useSalary.ts` не имел `saveProfile` в массиве зависимостей.
   - *Решение:* Все замечания устранены, ошибки логируются, типы и зависимости выверены.

## 8. Logic Problems (Проверка краевых случаев)

1. **Календарные дни против фиксированных 22 дней:**
   - В расчётах нормы часов для графика 5/2 исключено фиксированное предположение о 22 рабочих днях. Функция `getWorkingDaysInMonth(year, month)` точно рассчитывает количество будних дней конкретного месяца.
2. **Приоритет расчёта заработка:**
   - Строго соблюдён контракт приоритета: `Фактические отработанные часы / смены` → `Плановые показатели` → `Производственный календарь` → `Прогноз`.
3. **Испытательный срок:**
   - Почасовая ставка переключается автоматически: для дней до даты `probation_end_date` применяется ставка испытательного срока (442 ₽/ч), для последующих — постоянная ставка (497 ₽/ч).
4. **Недопущение дублирования доходов:**
   - Расчётный заработок в календаре зарплаты остаётся начисленным (accrued) и переходит в статус фактического дохода (`finance_operations`) только по явному действию пользователя («Подтвердить выплату»).

## 10. Calculation Problems & Precision

- **Округление и денежные суммы:**
  - Все промежуточные операции с валютой выполняются с точностью до копеек (`Math.round(val * 100) / 100`).
  - Стоимость смены девушки рассчитывается по утвержденной формуле:  
    `Обычная смена = (1900 + 200) * 1.15 = 2 415 ₽`  
    `Праздничная смена = (1900 * 2 + 200) * 1.15 = 4 600 ₽`  
    `Сдельная оплата = количество дел * 7 * 0.25 = количество дел * 1.75 ₽`.
  - Отсутствуют вычеты НДФЛ: ставки 442 ₽/ч и 497 ₽/ч трактуются как чистый доход (net).

## 11. Database Problems

- **Целостность внешних ключей:**
  - Таблицы `salary_rates`, `salary_work_days`, `salary_payments`, `salary_goals` имеют внешние ключи с каскадным удалением (`on delete cascade`) к `salary_profiles`, гарантируя отсутствие висячих записей.
  - Таблица `salary_payments` ссылается на `finance_operations` с опцией `on delete set null`, чтобы удаление операции в леджере не уничтожало историю зарплатного платежа.
- **Уникальные индексы:**
  - Добавлены ограничения `unique(salary_profile_id, date)` для смен и `unique(salary_profile_id, month)` для зарплатных целей, исключающие коллизии при параллельной записи.
- **Триггеры обновления:**
  - Для всех зарплатных таблиц установлены триггеры `set_updated_at()`.

## 12. RLS & Security Problems

- **Строгая изоляция пользователей:**
  - Для всех 5 таблиц зарплатного модуля включен RLS (`alter table ... enable row level security`).
  - Политики доступа жестко ограничивают выборку, вставку, изменение и удаление условием `auth.uid() = user_id` как в `USING`, так и в `WITH CHECK`.
  - Доступ без авторизации (`anon`) к зарплатным данным заблокирован на уровне СУБД.
- **Edge Functions:**
  - Доступ к Telegram Webhook защищен проверкой входящего заголовка `x-telegram-bot-api-secret-token`. При несовпадении немедленно возвращается `401 Unauthorized`.

## 13. Performance Problems

- **Предотвращение overfetching:**
  - Запросы к `salary_work_days` ограничены диапазоном дат просматриваемого месяца.
  - Сводные данные кешируются TanStack Query с инвалидацией только при реальных мутациях (`onSuccess`).
- **Бандл и динамические импорты:**
  - Разделы приложения, включая модуль зарплаты, вынесены в асинхронные чанки через `React.lazy`.
  - Размер финального gzip-бандла ядра приложения составляет всего ~63.5 КБ.
