# FinTrack AI 2.2

**Трекер личных финансов в рублях, который не теряет данные.** Веб-приложение + Telegram-бот, один аккаунт Supabase, офлайн-режим и честная аналитика по вашим собственным цифрам.

> [!IMPORTANT]
> Версия 2.0 — это полная переработка после аудита версии 1.0. Исправлены все найденные баги (потеря данных при сбое сети, перезапись истории целиком, недостижимый статус «Оплачен», тупик со сбросом пароля, «зашитый» график, бюджеты «за всё время», сдвиг дат из-за UTC, копейки в суммах и др.). Подробности — в [docs/QA-отчёт.md](docs/QA-отчёт.md) и [CHANGELOG.md](CHANGELOG.md).

Демо без регистрации: **`index.html?demo=1`** (или `?demo=1` на размещённом сайте) — внутри 280+ вымышленных операций за год, кредит с графиком, кредитка, цели, бюджеты. Есть и готовая страница `FinTrack-AI-demo.html` — открывается двойным щелчком и сама запускает демо.

Лендинг для публикации — `landing/index.html`: статическая страница без внешних ресурсов (шрифты, картинки и скрипты внутри файла), поэтому она открывается даже офлайн.

## Возможности

**Учёт**
- быстрое добавление текстом: «пятёрочка 1200 вчера», «билайн 900», «зарплата 80к», «такси 42,50» — разбор словарём, а при развёрнутой функции `ai-parse` и заданном ключе модели ещё и через LLM (словарь остаётся фолбэком);
- **голосовой ввод** (кнопка с микрофоном в быстром вводе): речь распознаётся на сервере, расшифровка попадает в поле, дальше обычный разбор; **фото чека** (кнопка с камерой) — модель со зрением читает итоговую сумму, дату и категорию и открывает форму с заполненными полями;
- полная форма операции: тип, сумма, дата, категория, счёт, описание;
- редактирование и удаление любой операции с кнопкой «Отменить»;
- импорт выписок банка из CSV с автоопределением колонок и предпросмотром;
- экспорт JSON (полная копия) и CSV (таблица операций);
- поиск и фильтры по типу, категории, месяцу.

**Аналитика**
- доходы/расходы/баланс за месяц со сравнением с прошлым месяцем;
- «можно тратить в день» с учётом обязательных платежей до конца месяца;
- график за 6 месяцев, расходы по категориям (SVG без внешних библиотек), расходы по дням;
- топ-5 расходов месяца и список категорий, которые растут быстрее всего;
- отчёт за месяц одной кнопкой (копируется в буфер).

**План и контроль**
- бюджеты на месяц **и на неделю (пн–вс)** по категориям: остаток, перерасход, предупреждения; недельные лимиты не мешают боту, который читает только месячные;
- финансовые цели с историей взносов и прогнозом даты достижения;
- повторяющиеся платежи: проведение одной кнопкой, напоминания попадают в «скоро списания»;
- кредиты с **настоящим графиком платежей** (проценты/тело/остаток), досрочным погашением и переплатой;
- кредитные карты: загрузка лимита, минимальный платёж, льготный период;
- счета с реальными остатками, календарь платежей, режим «до зарплаты».

**Данные**
- точечная запись в Supabase (`upsert` по `client_id`) — истории больше не перезаписываются целиком;
- очередь изменений и офлайн-кэш: без интернета приложение работает, изменения уходят сами;
- **защита от потери данных**: если облако не загрузилось, запись блокируется с понятным сообщением;
- живые обновления: операция из Telegram-бота появляется на сайте без перезагрузки;
- **учёт только в рублях** (₽): суммы и итоги всегда в одной валюте, поэтому они не смешиваются; если в банковской выписке встретятся «zł», «€» или «$», приложение покажет предупреждение и уберёт символы из описаний;
- **удаление аккаунта целиком** из приложения (Edge Function `delete-account`): операции, профиль, привязка Telegram и сам аккаунт;
- **архив всей истории одним файлом** (ZIP без сторонних библиотек): `operations.csv`, `operations.json`, `profile.json` и инструкция по восстановлению; приложение напомнит, если копии не было больше месяца;
- ночная выгрузка базы в GitHub Actions (`.github/workflows/backup.yml` + `scripts/backup.mjs`) — артефакт хранится 90 дней;
- RLS на все таблицы, публичный ключ без секретов.

**Интерфейс**
- **светлая и тёмная темы** — вручную или по системной настройке (`auto`), выбор запоминается на устройстве и синхронизируется через профиль;
- адаптив от 360 px, PWA-иконки, ярлыки «Новая операция» / «Операции» / «Telegram»;
- горячие клавиши: `N` — новая операция, `/` — поиск, `Esc` — закрыть окно, `?` — справка;
- тосты с «Отменить» вместо необратимого `confirm()`, доступные модальные окна с фокус-ловушкой, `aria-live`;
- **журнал диагностики** («Настройки → Диагностика»): последние 30 ошибок приложения и синхронизации — можно скопировать, скачать или проверить кнопкой «Проверить» (записывает тестовую ошибку). Если в `template.html` подключён Sentry, ошибки автоматически уходят и туда — код приложения для этого менять не нужно;
- всё в одном `index.html` без CDN — работает офлайн и открывается даже как локальный файл.

## Скриншоты

Скриншоты всех экранов проще всего посмотреть вживую: **`index.html?demo=1`**
(или страница `FinTrack-AI-demo.html`) — внутри готовая история за год с
кредитом, кредиткой, целями и бюджетами. Восстановление репозитория
сделало доступными исходники и тесты; снимки экрана в `docs/screenshots/`

## Быстрый старт

### Вариант 1. GitHub Pages (как сейчас)

1. Загрузите файлы в репозиторий (см. `./deploy.sh git@github.com:user/repo.git`).
2. **Settings → Pages → Source: GitHub Actions** — воркфлоу `pages.yml` сам соберёт и опубликует.
3. Приложение будет доступно на `https://user.github.io/repo/`.

### Вариант 2. Netlify / Vercel / Cloudflare Pages

Импортируйте репозиторий: сборка не нужна, публикуется корень (`netlify.toml` и `vercel.json` уже в репозитории). Заголовки безопасности и кэш настроены.

### Вариант 3. Локально

```bash
python3 -m http.server 8080     # затем http://localhost:8080/?demo=1
```

Сервис-воркер работает только по `http(s)`, поэтому для проверки офлайна нужен именно сервер, а не `file://`.

## Настройка Supabase

1. **SQL Editor** → выполните по порядку `supabase/migrations/001_init.sql`, затем `002_v2.sql`.
   Второй файл добавляет `account_id` у операций, `rules` и `settings` у профиля, индекс по категориям и view `finance_month_summary`. Оба файла идемпотентны.
2. **Authentication → Providers → Email**: включите провайдер. Рекомендуется **включить «Confirm email»** (в версии 1.0 регистрация была полностью открыта).
3. **Authentication → URL Configuration**: Site URL и Redirect URLs — адрес вашего сайта (для GitHub Pages: `https://user.github.io/repo/`). Иначе письма подтверждения и сброса пароля будут вести не туда.
4. **Database → Replication**: включите realtime для `finance_operations` и `finance_profiles`, если хотите мгновенное обновление между сайтом и ботом (без этого всё тоже работает, но с задержкой до минуты).
5. Приложение само определяет, есть ли новые колонки: со старой схемой оно продолжит работать (данные о счёте и правила просто не будут синхронизироваться).

Если вы обновляетесь с версии 1.0 — данные, ключи и таблицы остаются прежними, миграция ничего не удаляет.

## Telegram-бот и Edge Functions

Исходники **всех** серверных функций теперь лежат в репозитории — бот перестал быть «чёрным ящиком»:

```
supabase/functions/
  _shared/           cors.ts · supabase.ts (user/admin клиенты) · parse.ts · telegram.ts
  ai-parse/          разбор текста моделью; при отсутствии ключа отвечает словарём
  delete-account/    удаление аккаунта и всех данных (service_role внутри функции)
  telegram-webhook/  бот: /link · /today · /month · /budget · /credits · /unlink · /help
  credit-reminders/  напоминания о платежах по расписанию (cron + Telegram)
  weekly-digest/     воскресный дайджест «куда ушли деньги» (cron + Telegram)
```

Проверить функции можно без Deno, Supabase и ключей: `node tests/functions.mjs` подменяет окружение (`tests/deno-stub.mjs`) и прогоняет реальные сценарии — привязку, запись операции кнопкой, отчёты, удаление аккаунта, напоминания, дайджест и все отказы (401/403/429/413, выдуманная моделью сумма).

Команды бота: привязка через `/link КОД` (код берётся в разделе **Telegram AI**), отчёты за день и месяц, лимиты, ближайшие платежи. Раз в неделю приходит дайджест «куда ушли деньги», а напоминания о платежах — за 3 дня и в день платежа. Любая другая фраза — операция: бот показывает карточку с кнопками «Сохранить / Другая категория / Отмена» и пишет в базу только после подтверждения.

Что стоит проверить один раз:
- у вебхука задан `secret_token`, а функция отклоняет запросы без заголовка `X-Telegram-Bot-Api-Secret-Token`;
- в Supabase Secrets лежат `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `CRON_SECRET` и (по желанию) `AI_API_KEY` — `service_role` в клиент не попадает никогда;
- бот и сайт используют одни и те же категории и правила категоризации, поэтому «билайн 900» и там, и там попадает в «Мобильный оператор»;
- операция бота приходит с `client_id` вида `tg-…`, поэтому в истории не появляется дубликатов.

Пошаговая инструкция по разворачиванию — `supabase/functions/README.md`.

## Архитектура

```
index.html            ← собранный файл (то, что публикуется)
template.html + src/  ← исходники: 13 модулей вместо одного скрипта
  format.js   деньги (round2/sumMoney), локальные даты, утилиты
  state.js    состояние S, нормализация данных, локальный кэш, очередь изменений
  parse.js    распознавание текста: синонимы, даты, правила пользователя
  credits.js  график платежей кредитов, кредитные карты
  csv.js      экспорт/импорт CSV, разбор банковских выписок
  charts.js   SVG-графики (линия, столбцы, пончик) — без Chart.js
  cloud.js    Supabase: вход, синхронизация, outbox, realtime, офлайн
  ui.js       модальные окна, тосты с отменой, иконки, делегирование событий
  views*.js   экраны: главная, операции, аналитика, бюджеты, цели, кредиты…
  app.js      запуск, авторизация, восстановление пароля, демо-режим
build.mjs             ← сборка: node build.mjs → index.html
sw.js                 ← офлайн-кэш приложения
landing/index.html    ← страница-лендинг (статическая, без внешних ресурсов)
scripts/backup.mjs    ← ночная выгрузка данных для GitHub Actions
supabase/migrations/  ← SQL-миграции
supabase/functions/   ← исходники всех Edge Functions (включая Telegram-бота)
tests/                ← юнит-тесты, прогон интерфейса в jsdom, сквозные проверки, скриншоты
```

Почему так: в версии 1.0 один файл на 74 КБ из одной строки невозможно было ни ревьюить, ни тестировать. Теперь логика разделена, покрыта тестами и собирается одной командой; при этом публикуется по-прежнему **один самодостаточный HTML** — без сборщиков, зависимостей и CDN.

## Тесты

```bash
npm install              # jsdom + puppeteer для тестов (один раз)
node build.mjs           # собрать index.html из src/
node tests/unit.mjs      # 112 проверок: деньги, даты, парсер, график кредита, CSV, рубли, недельные бюджеты, ZIP-архив
node tests/smoke.mjs     # 73 проверки интерфейса в jsdom: все экраны, быстрый ввод, темы, диагностика, бэкап, офлайн
node --experimental-strip-types --import ./tests/deno-stub.mjs tests/functions.mjs
                         # 106 проверок Edge Functions (Deno, Supabase и ключи не нужны)
node tests/e2e-browser.mjs  # 18 сквозных проверок в настоящем Chrome (без Chrome — корректный пропуск)
```

Один командой: `npm test` (сборка + юнит + интерфейс + функции).

`tests/unit.mjs` ловит именно те ошибки, что были в 1.0: накопление копеек, сдвиг даты на сутки, `«80к» → 80`, неверный график кредита. `tests/functions.mjs` уже нашёл ошибки в серверных функциях (в том числе клавиатуры бота мимо поля `reply_markup` — см. `supabase/functions/README.md` и `docs/QA-отчёт.md`), а тест ZIP разбирает архив вручную и сверяет контрольные суммы независимым CRC32 из `node:zlib`. Отдельные блоки проверяют, что учёт ведётся только в рублях (старые настройки с чужой валютой приводятся к рублю, символы валют убираются из импорта), границы недели (пн–вс) и раздельность месячных и недельных лимитов. В CI (`.github/workflows/tests.yml`) тесты запускаются на каждый push и падают, если `index.html` не пересобран из `src/`; `.github/workflows/functions.yml` дополнительно прогоняет `deno check` по функциям.

## Безопасность

- В клиенте только publishable-ключ Supabase — это безопасно, доступ к строкам закрыт RLS-политиками.
- Секретов в репозитории нет; `service_role` и токен бота живут только в Supabase Secrets.
- Автоматический тест (`tests/smoke.mjs`, блок 7) проверяет, что при сбое загрузки приложение не пишет в базу вообще ничего.
- Учитывая, что репозиторий публичный: держите включённым подтверждение почты, следите за лимитами Auth и Edge Functions.
